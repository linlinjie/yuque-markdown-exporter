# 语雀表格/看板导出设计（v2）

## 背景与问题

v1 通过在普通语雀文档地址后追加：

```text
/markdown?plain=true&linebreak=false&anchor=false
```

读取 Markdown。语雀的表格/看板页面虽然与普通文档使用相同的 URL 结构，但实际是 Lakex 结构化数据视图，不提供上述 Markdown 地址，因此请求会返回 HTTP 404。

实际页面检查确认：

- 看板和表格通过页面内的选项卡切换，选中的视图写入 `#view:...`。
- 接口响应可能加密，但浏览器解密并渲染后，字段名和字段值以明文存在于 DOM。
- 看板横向排列分组，每个分组使用独立的虚拟滚动容器（已观察到 `data-testid="virtuoso-scroller"`）。只读取当前 DOM 会遗漏未滚动到的卡片。
- 表格视图提供语义化的表头和数据行，字段顺序稳定，适合作为统一采集入口。

因此 v2 不破解接口加密，也不依赖未公开的语雀接口，而是在用户当前有权访问的页面内，按需采集已经解密并渲染的表格数据。

## v2 第一版范围

支持当前打开的单个语雀结构化表格/看板：

- 识别结构化表格或看板，避免继续把 404 当成登录或权限错误。
- 从看板进入时，临时切换到已有的“表格视图”进行采集。
- 导出该“表格视图”自身当前配置的筛选、分组和排序结果。
- 生成 Markdown 表格，支持查看、复制和下载 `.md`。
- 同时支持下载 `.csv`，便于处理宽表和二次分析。
- 保留空字段、链接文本与地址、人员名称、多选标签、日期及普通文本。
- 全部处理在当前浏览器本地完成，不上传、同步或持久化表格内容。

第一版不包含：

- 跨多个表格或整本知识库批量导出。
- 绕过当前用户权限读取隐藏记录。
- 还原附件二进制内容、公式计算逻辑、评论或记录历史。
- 将看板分组布局原样还原为 Markdown 看板。
- 自动清除筛选条件以导出底表全部记录。

> 注意：看板视图与表格视图可以各自保存筛选条件。从看板触发导出时，v2 导出的是切换后“表格视图”的当前结果，不宣称等同于看板当前筛选结果。

## 方案比较

### 方案 A：表格 DOM 采集（采用）

按需注入内容脚本，切换到表格视图，自动滚动虚拟列表并收集明文行列。

优点：不处理密文，不需要 Token，不依赖私有接口，数据不离开本机；表格比看板更容易准确对齐字段。缺点：依赖页面 DOM 结构，语雀大版本更新后可能需要调整选择器。

### 方案 B：逐列采集看板

横向遍历分组，再分别纵向滚动每个看板列。

优点：可以保留看板分组语义。缺点：多个独立虚拟列表导致漏项风险和采集时间显著增加，字段结构也不如表格稳定。第一版不采用。

### 方案 C：Hook 解密或读取语雀内部状态

拦截页面解密过程，或读取框架内部状态。

优点：理论上可一次获得完整结构化数据。缺点：强依赖语雀内部实现，安全风险和维护成本高，页面升级后容易失效。第一版不采用。

## 用户流程

1. 用户登录语雀并打开普通文档、表格或看板。
2. 用户点击扩展，扩展只检查当前标签页。
3. 若检测到表格/看板选项卡，弹窗显示“已识别语雀表格/看板”，使用结构化导出界面。
4. 用户选择“查看 Markdown”“复制 Markdown”或导出 Markdown/CSV。
5. 若当前处于看板，扩展提示并临时切换到“表格视图”。
6. 扩展按当前表格视图的筛选、分组和排序逐批采集记录。
7. 只有在采集通过完整性检查后才生成文件或复制内容。
8. 采集结束后尽量恢复用户原来的视图和滚动位置；恢复失败只告警，不影响已验证的数据结果。

普通语雀文档继续沿用 v1 工作流，功能和输出保持兼容。

## 架构设计

### 页面识别

弹窗打开后利用 `activeTab` 和 `chrome.scripting` 按需执行轻量检测：

- URL 仍需属于 `yuque.com` 或其子域名。
- 页面存在名为“表格视图”或“看板视图”的 `role="tab"` 时，判定为结构化页面。
- 未检测到结构化视图时，继续按普通文档处理。
- 如果检测时页面尚未渲染，而 `/markdown` 返回 404，则再执行一次结构化页面检测；仍未识别才显示原始 HTTP 错误。

HTTP 错误对象需要保留状态码，避免把所有非 2xx 响应都混为登录或权限问题。

### 按需内容脚本

新增 `scripting` 权限，但不配置常驻 `content_scripts`。只有用户打开扩展并触发结构化导出时，才向当前活动标签页注入采集脚本。

内容脚本职责：

- 找到并切换“表格视图”。
- 等待表格、表头和首批数据行稳定。
- 识别表格的纵向滚动容器及必要时的横向滚动容器。
- 采集当前已渲染行，滚动后继续采集并去重。
- 把标准化后的 `{ columns, records, metadata }` 返回弹窗。
- 在 `finally` 中恢复视图和滚动位置。

弹窗职责：

- 根据页面类型切换文档导出或表格导出 UI。
- 接收采集结果并转换为 Markdown/CSV。
- 完成查看、复制与下载。
- 展示采集阶段、记录数、告警和错误。

### 记录采集与虚拟滚动

表头按页面显示顺序生成字段列表。每次采集只处理当前已渲染的数据行：

1. 排除表头、分组标题、统计行和“添加记录”等非记录行。
2. 优先使用 DOM 暴露的虚拟列表索引或稳定行标识作为键。
3. 若没有稳定标识，使用可见行号与主字段文本组成键，并用整行规范化内容指纹防止误合并。
4. 依据字段元素的 DOM 顺序或横向位置与表头对齐；缺少内容的字段写为空字符串，不能通过压缩文本猜测列位。
5. 将链接保存为 `{ text, href }`，人员与多选值保存为字符串数组，其他类型保存为规范化文本。
6. 逐步滚动到容器底部；到达底部且连续三轮没有新增记录后结束。
7. 若页面水平虚拟化列，则分段横向滚动，并按稳定记录键合并列数据。

采集设置 120 秒总上限。发生以下任一情况时失败且不生成文件：

- 找不到表格或字段列表为空。
- 表格存在数据但一条有效记录也未采集到。
- 滚动未到达底部且已超时。
- 同一记录出现无法解释的字段冲突。
- 页面在采集期间切换到其他文档或表格。

如果页面没有暴露总行数，完整性以“已到达底部、连续稳定轮次、无记录冲突”为准；输出元数据注明这是当前视图采集结果。

### 中间数据模型

```js
{
  title: "表格标题",
  sourceUrl: "https://team.yuque.com/...",
  viewName: "表格视图",
  filtersActive: true,
  columns: [
    { id: "column-0", name: "事项", type: "text" },
    { id: "column-1", name: "状态", type: "select" }
  ],
  records: [
    {
      key: "record-key",
      values: {
        "column-0": "示例事项",
        "column-1": ["进行中"]
      }
    }
  ]
}
```

字段类型识别失败时统一降级为纯文本，不阻断导出。

## 输出格式

### Markdown

```markdown
# 表格标题

> 来源：<原语雀地址>
> 导出范围：当前表格视图（保留筛选、分组和排序）

| 事项 | 状态 |
| --- | --- |
| 示例事项 | 进行中 |
```

- 转义 `|`、反斜杠和单元格内换行。
- 单个链接输出 `[文本](URL)`；只有 URL 时直接输出 URL。
- 多个人员或标签使用 `、` 连接。
- 分组不插入伪造的数据行；当前视图分组信息只用于记录顺序。

### CSV

- UTF-8 BOM，提升 Excel 中文兼容性。
- 第一行为字段名。
- 双引号、逗号和换行按 RFC 4180 规则转义。
- 多值字段使用 `；` 连接。
- 链接字段优先保留 URL；同时有显示文本时输出 `文本 <URL>`。

## UI 变化

普通文档保持现有界面。结构化页面中：

- 状态改为“已识别语雀表格/看板”。
- “查看 Markdown”和“复制 Markdown”保留。
- 原图片处理选项替换为“Markdown (.md)”与“CSV (.csv)”。
- 执行期间显示“正在切换表格视图”“正在采集记录”“正在生成文件”等阶段。
- 结果显示实际导出的记录数与字段数。
- 失败时明确说明没有生成残缺文件。

## 权限与隐私

新增权限：

- `scripting`：只在用户主动使用扩展时向当前活动语雀页面注入采集脚本。

继续使用：

- `activeTab`：限制到用户当前操作的标签页。
- `clipboardWrite`：复制生成的 Markdown。
- 语雀域名权限：普通文档读取 Markdown。

不读取 Cookie、Authorization、Token、Local Storage 或浏览历史；不调用外部服务；不持久化表格内容；不修改语雀记录。

## 测试与验收

自动化测试覆盖：

- 404 状态保留及结构化页面回退判断。
- 表头与记录规范化，包括空字段、多选、人员、日期和链接。
- 分组标题、统计行等非记录内容的排除。
- 虚拟滚动去重、稳定结束、超时与冲突失败。
- Markdown 转义和链接输出。
- CSV BOM、引号、逗号与换行转义。
- 普通文档 v1 工作流回归。
- Manifest 新权限和内容脚本文件完整性。

Chrome 手工验收：

1. 普通语雀文档仍可查看、复制和导出 Markdown。
2. 从表格视图导出时，结果与当前筛选后的行数和字段顺序一致。
3. 从看板触发时可切到表格、完成采集并恢复原视图。
4. 包含长分组的虚拟列表可采集到最后一条记录。
5. 空字段、链接、人员、多选标签和日期不串列。
6. Markdown 与 CSV 可被常用编辑器正常打开。
7. 采集超时或页面结构不兼容时不生成残缺文件。

## 后续可选增强

- 直接按看板分组导出 Markdown 标题与卡片列表。
- 让用户选择某一个表格视图，而非固定使用已有“表格视图”。
- 在用户明确确认后临时清除筛选，导出底表全部记录并恢复设置。
- 支持附件下载、JSON 输出与批量表格导出。
