# 语雀 Markdown 导出器设计规格

## 目标

构建一个 Chrome Manifest V3 扩展，识别当前标签页中的单篇语雀文档，并提供查看 Markdown、复制 Markdown、导出 Markdown，以及将远程图片本地化后导出 ZIP 的能力。

首版只处理当前打开的单篇文档，不支持知识库批量导出。

## 产品交互

用户点击浏览器工具栏中的扩展图标后打开弹窗。弹窗显示当前页面是否为受支持的语雀文档，并在支持时提供以下操作：

1. **查看 Markdown**：在新标签页打开文档对应的 Markdown 地址。
2. **复制 Markdown**：读取 Markdown 原文并复制到系统剪贴板。
3. **导出**：通过单选项选择导出模式：
   - **保持图片原地址**：下载单个 `<文档标题>.md` 文件。
   - **下载图片到本地**：下载文档引用的远程图片，将成功下载的图片链接改写为 `images/...`，并生成 `<文档标题>.zip`。

弹窗展示操作进度、成功结果和可执行的错误提示。用户关闭弹窗后，不保证仍在后台继续尚未完成的导出。

## URL 识别和规范化

支持 `https://yuque.com/*` 和 `https://*.yuque.com/*`。当前 URL 必须满足以下条件：

- 使用 `http:` 或 `https:` 协议；
- 主机名为 `yuque.com` 或以 `.yuque.com` 结尾；
- 路径至少包含两个非空片段；
- 不属于明确的非文档入口，如登录、搜索、通知和账户设置页面。

转换规则为：先去掉现有的 `/markdown` 后缀（如果有），再在文档路径后追加 `/markdown?plain=true&linebreak=false&anchor=false`。原页面的查询参数和片段标识不传递到 Markdown 地址。

首版以保守规则识别文档。若某个语雀系统页面形似文档 URL 但 Markdown 请求失败，弹窗显示读取失败，不尝试抓取页面 DOM。

## 架构与组件

扩展不依赖服务端，文档内容仅在浏览器本地处理。

- `manifest.json`：声明 Manifest V3、弹窗、语雀主机权限、剪贴板和按需图片域名权限。
- `popup/`：渲染状态、导出选项和操作按钮，协调当前标签页与导出流程。
- `lib/yuque-url.js`：识别语雀文档 URL，并生成规范化 Markdown URL。
- `lib/markdown.js`：提取 Markdown 图片和 HTML `<img>` 引用，并将成功下载的引用改写为本地路径。
- `lib/filename.js`：生成跨平台安全文件名并推断图片扩展名。
- `lib/exporter.js`：读取 Markdown、下载图片、汇总部分失败结果，并生成导出文件。
- `lib/zip.js`：生成无需第三方依赖的 ZIP 文件，避免构建步骤和供应链依赖。

纯逻辑模块使用 ECMAScript Modules，并保持浏览器与 Node 测试环境都可导入。

## 数据流

### 弹窗初始化

1. 使用 `chrome.tabs.query` 获取当前活动标签页。
2. 通过 URL 模块判断是否为语雀文档。
3. 不支持时禁用操作按钮并解释原因；支持时显示文档标题和导出选项。

### 查看 Markdown

1. 生成规范化 Markdown URL。
2. 使用 `chrome.tabs.create` 在新标签页打开。

### 复制或直接导出 Markdown

1. 使用扩展页面的跨域读取能力访问 Markdown URL，并携带当前语雀登录态。
2. 检查 HTTP 状态和返回内容。
3. 复制时写入剪贴板；直接导出时生成 UTF-8 Markdown Blob 并触发下载。

### 图片本地化导出

1. 读取 Markdown 原文。
2. 提取标准 Markdown 内联图片和 HTML `<img src="...">` 中的绝对 HTTP(S) URL；`data:`、相对路径和非 HTTP(S) URL 保持不变。
3. 对图片 URL 去重，并从 URL 收集所需主机来源。
4. 弹窗列出尚未授权的图片域名并显示“授权并导出”；用户再次点击后，直接从该点击事件调用 Chrome 可选主机权限 API。用户拒绝时终止本次本地化导出，并提示仍可选择“保持图片原地址”。两段式交互确保权限申请满足 Chrome 的用户手势要求。
5. 下载图片。文件名按文档内首次出现顺序生成，例如 `images/image-001.png`；扩展名优先来自响应 `Content-Type`，其次来自 URL，最终回退为 `.bin`。
6. 仅改写成功下载的图片引用。失败的引用保留远程地址。
7. 将改写后的 Markdown 和成功下载的图片加入 ZIP，并触发下载。
8. 弹窗展示图片成功数和失败数；部分图片失败不阻止 ZIP 生成。

同一远程 URL 在一篇文档中只下载一次，所有对应引用改写为同一个本地路径。不同远程 URL 即使文件名相同，也不会覆盖。

## 权限与隐私

固定权限只覆盖运行扩展所需能力和语雀域名。图片域名使用 `optional_host_permissions` 按实际文档引用申请，不默认获得所有网站读取权限。

扩展不会：

- 将文档或图片发送到第三方服务；
- 保存浏览历史或文档内容；
- 在语雀页面中注入悬浮控件；
- 修改原始语雀文档。

## 错误处理

弹窗必须区分并提示以下情况：

- 当前页面不是受支持的语雀文档；
- 当前标签页 URL 不可读取；
- Markdown 请求返回非成功状态；
- 登录态失效或被重定向到 HTML 登录页面；
- Markdown 响应为空；
- 剪贴板写入失败；
- 用户拒绝图片域名权限；
- 所有图片或部分图片下载失败；
- ZIP 生成或浏览器下载失败。

操作进行中禁用重复触发按钮。失败后恢复可操作状态，不保留半成品文件。

## 测试策略

自动化测试使用 Node 内置测试框架，不引入测试依赖。测试覆盖：

- 语雀根域名和企业子域名识别；
- 非语雀域名、系统页面和无效 URL 拒绝；
- 普通文档 URL、已有 `/markdown` URL 的规范化；
- 文件名非法字符、空标题和长度限制；
- Markdown 图片、HTML 图片、重复图片和无需处理的 URL；
- 下载成功、部分失败、完全失败时的正文改写与汇总；
- 图片扩展名推断；
- ZIP 目录项、文件内容和 UTF-8 文件名；
- Manifest 基本字段和本地文件引用完整性。

手工验收使用已登录的 Chrome：

1. 在普通网页打开弹窗，确认操作被禁用。
2. 在企业语雀单篇文档打开弹窗，确认查看 Markdown 可用。
3. 复制 Markdown，确认内容与 `/markdown?plain=true&linebreak=false&anchor=false` 页面一致。
4. 导出原地址模式，确认 `.md` 文件名和内容正确。
5. 导出本地图片模式，确认权限请求、ZIP 结构、图片路径改写和解压后的图片可打开。
6. 使用包含不可访问图片的文档，确认仍生成 ZIP 并保留失败图片原链接。

## 交付物与非目标

交付物包括可直接通过 Chrome“加载已解压的扩展程序”安装的源码、自动化测试和中文使用说明。

首版不包含：

- 整个知识库或目录的批量导出；
- 定时同步；
- 将 Markdown 上传到其他平台；
- 将图片转为 Base64；
- 解析并下载非图片附件；
- Firefox、Edge 商店或 Chrome Web Store 发布包。
